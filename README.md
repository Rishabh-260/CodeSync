# CodeSync

A small-team collaborative code editor built with React, Vite, Monaco, Yjs, Hocuspocus, Express, PostgreSQL, and Rustbox.

## Local development

Requirements: Node.js 22+ and npm.

1. Copy `.env.example` to `.env` and set your Neon `DATABASE_URL` and `DATABASE_URL_DIRECT`. Set `JWT_ACCESS_SECRET` to a random value with at least 32 characters. `RUSTBOX_API_KEY` is required to run code; account and room features work without it.
2. Install dependencies with `npm install`.
3. Apply the schema with `npm run db:migrate`.
4. Start the frontend and backend with `npm run dev`.

The app runs at `http://localhost:5173`. The API and collaboration WebSocket share `http://localhost:10000`; the socket endpoint is `/collab`.

## Deploy

### Neon

Create a Neon PostgreSQL database. Set `DATABASE_URL` to its pooled connection URI for the running API and `DATABASE_URL_DIRECT` to its direct connection URI for Drizzle migrations. Preserve Neon’s TLS parameters in both URLs.

### Render

Connect this repository and deploy the included `render.yaml` blueprint. Configure:

- `DATABASE_URL` and `DATABASE_URL_DIRECT` from Neon.
- `FRONTEND_ORIGINS` as a comma-separated list of the production Vercel app origin and any preview origins you want to allow.
- `RUSTBOX_API_KEY` from the Rustbox dashboard.
- `JWT_ACCESS_SECRET` is generated by the blueprint.

Use an always-on Render web service for live collaboration. The service serves REST and WebSocket traffic on the same port. Hocuspocus room snapshots are stored as Yjs binary state in PostgreSQL. Render sends `SIGTERM` on instance replacement; the server flushes pending Hocuspocus document stores before closing.

### Vercel

Import the repository as a Vercel project using the root directory. `vercel.json` builds the `@codesync/web` workspace and routes SPA deep links to `index.html`. Set:

- `VITE_API_URL=https://api.example.com/api`
- `VITE_WS_URL=wss://api.example.com/collab`

Use custom domains such as `app.example.com` for Vercel and `api.example.com` for Render under the same parent domain. This keeps the API refresh cookie same-site while requests remain credentialed cross-origin. Leave `COOKIE_DOMAIN` unset so the refresh cookie is host-only to the API. Configure `FRONTEND_ORIGINS` to exactly include the Vercel app origin(s), without trailing slashes.

The Render pre-deploy command applies Drizzle migrations using `DATABASE_URL_DIRECT`.

## Product behavior

- Accounts use email/password; access JWTs stay in browser memory and refresh tokens are HttpOnly cookies.
- Any authenticated user with the room invite can join and edit. The room creator can rotate the invite and delete the room.
- Each room has one shared text document and a shared JavaScript/Python selection. There is no chat, multi-file tree, offline guarantee, or run history.
- Execution is proxied through the backend. The Rustbox key is never exposed to the browser. The UI supports JavaScript and Python, stdin, stdout/stderr, and verdicts. The current Rustbox Judge profile applies its own CPU, wall-time, and memory caps.
- Application execution limits are one concurrent run per user and five runs per minute. These in-memory limits assume a single Render backend instance; use a shared limiter before scaling to multiple instances.

## Operational notes

- Rustbox is an external execution provider; review its current API availability, quotas, and beta terms before production use. Code and stdin are sent to Rustbox to execute.
- Keep Vercel preview domains out of `FRONTEND_ORIGINS` unless they should be allowed to call the API.
- Change `COOKIE_DOMAIN` only if you intentionally need a parent-domain cookie.
- `npm run db:generate` creates a migration after schema changes. Commit the generated SQL and journal updates.
